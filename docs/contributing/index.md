# Contributing

Contributions to Gyselalib++ are welcome. This section describes how to propose changes and the conventions that your code and documentation should follow.

1. **Discuss your contribution** : Read the [contribution guidelines](../CONTRIBUTING.md). Bug reports are always welcome, but new features and significant changes should be discussed with the core team before any work begins.

2. **Choose where to work** : Decide whether your work belongs [on GitHub or in a private repository](../troubleshooting/developer_FAQ.md#should-i-create-a-branch-in-the-library-on-github-or-in-a-private-repository-eg-on-gitlab), then [create a branch](../how_to/Using_git.md#branches).

3. **Follow the coding standard** : Write your code following the [coding standard](CODING_STANDARD.md), which describes naming conventions, style, GPU management and how code should be organised.

4. **Check your code** : Run the [static analysis](../how_to/Development_tips.md#cppcheck) and make sure the tests pass.

5. **Document your changes** : Follow the guide to [writing documentation](Adding_docs.md) to document new code in the API and in the `README.md` files, and record your changes in the [changelog](../../CHANGELOG.md).
